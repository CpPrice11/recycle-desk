# Збірка та випуск Recycle Desk

[До README](../README.md)

Програма використовує Rust і Win32. Для основної збірки потрібні Rust stable MSVC, Visual Studio Build Tools із Windows SDK та Inno Setup для інсталятора.

## Збірка

Виконайте з кореня репозиторію:

```powershell
cargo fmt --check
cargo test --locked
./scripts/build.ps1
$compiler = ./scripts/setup-inno.ps1
./scripts/package.ps1 -Iscc $compiler
```

EXE з’явиться в `target/x86_64-pc-windows-msvc/release/`, пакети — у `dist/`. Скрипт основної збірки включає статичне середовище C. Іконка вже є в репозиторії; її файли описані в [довідці](../resources/icons/README.md).

Альтернативна GNU-збірка потребує GNU Rust toolchain і LLVM-MinGW із `windres` у `PATH`:

```powershell
./scripts/build.ps1 -Gnu
$compiler = ./scripts/setup-inno.ps1
./scripts/package.ps1 -Target native -Iscc $compiler
```

## Перевірки

`cargo test --locked` перевіряє локалізацію, обробку зображень, іконки й оновлювач. Інтеграційні перевірки Windows запускаються окремо:

```powershell
./scripts/test-live.ps1 -Exe target/x86_64-pc-windows-msvc/release/recycle-desk.exe
./scripts/test-updater.ps1
```

Перший сценарій створює власні контрольні файли, переміщує їх у кошик, перевіряє мініатюру, відновлення байтів і остаточне видалення вибраного. Він не очищує весь кошик. Другий перевіряє заміну тестового EXE, перезапуск і збереження налаштувань у `test-output/`. Запускайте інтеграційні перевірки в окремому тестовому середовищі Windows.

У GitHub Actions для v0.1.2 пройшли сім модульних тестів, інтеграційна перевірка Windows Shell, збірка, пакування та перевірка підпису. Це не замінює візуальної перевірки інтерфейсу. Windows 10, повний сценарій UI, фізичні монітори з різним DPI та автооновлення встановленої через Inno Setup програми окремо не перевірені.

## Підписані оновлення

Адреса GitHub-репозиторію вбудовується зі змінної `GITHUB_REPOSITORY`. Для локальної збірки її можна задати через `RECYCLE_DESK_REPOSITORY=owner/repository`. Відкритий ключ зберігається в `resources/update-public.key`. Без адреси чи ключа перевірка оновлень неактивна.

Для випусків цього проєкту використовується чинна пара ключів. Приватний ключ зберігайте поза репозиторієм із захищеною резервною копією. У GitHub Actions потрібен секрет `RECYCLE_DESK_SIGNING_KEY`: Base64-подання 64-байтової пари ключів. Не замінюйте ключ під час звичайного випуску: наявні копії програми довіряють вбудованому відкритому ключу.

Для окремого проєкту нову пару створює команда нижче. `PRIVATE` та `PUBLIC` — шляхи до нових файлів; наявні файли команда не перезаписує.

```powershell
cargo run --example release_sign -- gen-key PRIVATE PUBLIC
```

Пакет `RecycleDesk-X.Y.Z-windows-x64-update.zip` містить `recycle-desk.exe`, `README.md`, `LICENSE` і `THIRD_PARTY_NOTICES.txt`. У ньому немає `portable.flag` або налаштувань. Ed25519ph-підпис прив’язаний до назви архіву; перейменований, змінений або підписаний іншим ключем пакет відхиляється. Підпис повторно перевіряється перед заміною EXE. Каталог програми має бути доступним для запису.

## GitHub Releases

1. Оновіть `version` у `Cargo.toml` і відповідний запис `Cargo.lock`.
2. Створіть і надішліть тег `vX.Y.Z`, що збігається з версією пакета.
3. Дочекайтеся завершення workflow: він перевіряє код, збирає portable ZIP та інсталятор, підписує update ZIP і створює `SHA256SUMS.txt`.
4. Перегляньте файли й опис у створеній чернетці GitHub Release та опублікуйте її.

Звичайні коміти й чернетки релізів не запускають оновлення встановлених копій. Програма отримує лише новіші стабільні опубліковані версії. Ручний запуск workflow створює артефакти без публікації релізу. Опубліковані теги й файли релізів не змінюйте.

Підпис пакета оновлень і сертифікат Authenticode — окремі механізми. EXE та інсталятор поки не мають Authenticode.
