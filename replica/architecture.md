# Архітектура

Rust + Microsoft windows-rs, Win32 common controls, Windows Shell COM. Один процес, один message loop; COM STA у потоці роботи з Shell. Немає вебсервера, WebView чи БД. Мережа потрібна лише для GitHub-оновлень.

- `shell.rs`: перелік Shell Recycle Bin, властивості, канонічний IContextMenu undelete для відновлення, IFileOperation для остаточного видалення; підсумок SHQueryRecycleBinW.
- `ui.rs`: системний ListView, edit, кнопки й меню; стан/індекси вибору належать вікну. Асинхронне читання передає готові дані через повідомлення, COM-об’єкти не передаються між потоками.
- Мініпрев’ю: `shell::preview` отримує bitmap саме переробленого Shell-об’єкта через `IShellItemImageFactory`, а не відкриває початковий шлях. `images.rs` звільняє GDI-ресурси та передає лише BGRA-пікселі між потоками. Один фоновий пакет, видимі рядки плюс два, максимум 96 кешованих прев’ю; покоління кешу відхиляє застарілі відповіді. ImageList належить застосунку (`LVS_SHAREIMAGELISTS`) і звільняється при приховуванні.
- `settings.rs`: невеликий текстовий INI; portable marker поряд із EXE, інакше LocalAppData; перевірка значень, атомарне збереження. Автозапуск у HKCU лише явним перемикачем.
- `text.rs`: однаковий набір ключів uk/en, множина й одиниці розміру.
- `main.rs`: запуск, single-instance, tray-only аргумент, діагностика/контрольні перевірки.

Shell PIDL ідентифікує об’єкт; відображені назви не використовуються як довірені файлові шляхи для видалення. Не обходити Windows ACL. Не перезаписувати зайнятий шлях при відновленні мовчки. Після кожної операції перечитати стан і показати частковий збій.

Розмір, RAM і CPU — фактичні вимірювання release-збірки, не обіцянки. Спочатку нативний наскрізний сценарій; потім налаштування/оформлення; далі перевірки та пакування.
